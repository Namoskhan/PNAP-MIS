# O1 index decisions before implementation

Evidence: `explain-before.json`, `indexes-before.json`, and `baseline-before.json`. Dataset: 384 members, 17 meetings, 3 activities, 4 responsibilities. These are reconstructed local measurements, not historical 50k results.

| Collection | Endpoint / current query | Current plan | Docs examined | Keys examined | Sort | Existing relevant indexes | Candidate | Reason / expected benefit | Risk | Classification |
|---|---|---|---:|---:|---|---|---|---|---|---|
| members | GET /api/members?scope=all&page=1&limit=25; filter {}, sort createdAt descending | PROJECTION_SIMPLE → SORT → COLLSCAN | 384 | 0 | Yes | No createdAt index | `{createdAt:-1}` | Read first 25 in index order instead of scanning/sorting 384. Also supports unchanged skip pagination and summary createdAt range count. | Additional write/storage cost; search planner may change; verify exact response order. Current 384 createdAt values are distinct. | STRONGLY JUSTIFIED |
| members | GET /api/members?provinceId=…&page=1&limit=25; equality on provinceId, createdAt descending | PROJECTION_SIMPLE → SORT → FETCH → IXSCAN | 192 | 192 | Yes | provinceId_1; provinceId_1_lastActivityAt_-1, neither provides createdAt order | `{provinceId:1,createdAt:-1}` | Equality prefix plus requested sort, reducing fetched records to the page size. | Extra write/storage cost; no claim for untested scope combinations. | STRONGLY JUSTIFIED |
| members | Unanchored case-insensitive OR regex on fullName/cnic/phone/memberId | SUBPLAN → PROJECTION_SIMPLE → SORT → COLLSCAN for find; COLLSCAN for count | 384 | 0 | Yes for find | Exact identity indexes already exist | Text/prefix/duplicate identity indexes | Ordinary B-tree indexes cannot solve arbitrary substring search; semantics must remain unchanged. | Changed search semantics or needless index cost | REJECT |
